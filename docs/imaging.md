# Imaging and carts (Phase 9)

Freo stores station IDs, sweepers, liners, promos, jingles, carts, and generic imaging as `ImagingAsset` records. They are separate from music tracks and categories. Audio probing and controlled staging use the same ffprobe and storage rules as music; uploaded filenames never become storage paths. Only MP3 is currently accepted. The web account can write to upload staging, while the dedicated non-root ingest worker writes approved files to the station's private `imaging` directory. Nginx and Flask do not serve these files directly.

In **Admin → Imaging**, upload one file, wait for validation, review its name/type/cart code, assign it to a group if desired, then verify and enable it. Accepted web uploads remain disabled by default. An exact duplicate checksum within the station returns the existing asset and creates no second file. Cart codes are optional, unique per station, and limited to letters, numbers, `_`, and `-`. A group can set a minimum repeat interval; the selector favors never-played and least recently confirmed assets, temporarily holds pending requests, and records a relaxation when necessary. Imaging never advances a music rotation cursor or participates in artist separation.

Clock editors accept **CART** for a specific asset UUID or cart code and **IMAGING_GROUP** for a pool. Preview is read-only. Validated slots enter the existing Liquidsoap request queue without restarting playout. Missing/disabled assets fail safely and the bounded clock scan proceeds to the next slot. History is recorded only after Liquidsoap confirms a start. Imaging plays sequentially; overlapping sweepers, ducking, intro ramps, and hard-timed legal IDs are future work. The `STATION_ID` type is classification, not hourly ID enforcement.

Disable excludes future selection; current or queued audio may finish. Decommission is a reversible database state change that retains the private file and confirmed history. It is blocked while a direct clock reference, queued request, or observed current playout exists. Physical deletion is intentionally deferred.

Root-run recovery CLI: `flask imaging list --station freo-demo`, `flask imaging ingest --station freo-demo --file /trusted/id.mp3 --type station_id --name 'Top of Hour ID'`, `flask imaging enable --station freo-demo ID-TOH`, and `flask imaging-group assign --station freo-demo --asset ID-TOH --group ids`. CLI ingestion also defaults disabled. The web UI and CLI call the same imaging service. Back up PostgreSQL and `/var/lib/freo/media` together. No imaging files belong in Git.

Each browser mutation requires an authenticated global admin and CSRF token and records a safe audit event. Group, asset, and clock target lookups are station-scoped. The local commit does not perform a fresh-VM installation test; that remains the public installability gate.
