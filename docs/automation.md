# Automation worker and playback confirmation

`freo-automation.service` runs one non-root worker as `freo-automation`. It is independent of the Flask web service and manages enabled stations one at a time within the loop, isolating per-station errors. It uses PostgreSQL for active rotation, cursor, selection decisions, and a heartbeat. It polls every two seconds and targets two pending Liquidsoap requests per station. Empty libraries back off for 30 seconds instead of spinning. The worker does not run sudo, control systemd, listen on TCP, read Icecast credentials, or write privileged radio configuration.

The worker belongs to the restricted `freo-playout` group so it can read approved media and connect to station Unix sockets. The `freo` web user is **not** in that group and cannot connect. Managed sockets are mode 0660; the independent diagnostic socket remains mode 0600. The queue adapter allows only queue inspection, active-request inspection, and pushes of internally resolved station UUID MP3 files with a committed decision ID. It never accepts a web-supplied command, socket path, or media path. One Liquidsoap process remains per station.

Liquidsoap's `request.queue` plays only Freo-supplied requests and falls back to generated audio when empty. Routine selections do not restart Liquidsoap. An `on_track` callback appends the numeric decision ID and its Unix start timestamp to a private station event file when the request actually starts. The worker reads those events and changes the decision from selected/queued to started; a preview or queue push alone is not play history. The worker also compares stored Liquidsoap request IDs with its live queue and on-air IDs. A vanished request becomes failed with a reason; a delayed authentic start event can correct that state. A worker restart replays the private event file idempotently; a Liquidsoap restart gives a new socket identity and pending old requests are marked failed before refill.

`GET /health/automation` requires a recent PostgreSQL heartbeat, not just an active systemd unit. `GET /api/stations/<slug>/automation/status` reports mode, active rotation, observed queue depth, and last selection/start times. `GET /api/stations/<slug>/history` includes only confirmed starts; `flask history list --station <slug>` and `flask automation explain --station <slug>` help operators audit decisions. The worker logs station, rotation, slot, category, track ID, relaxation, and queue failures to journald without source passwords. Managed Liquidsoap runs at warning log level so normal decoder information does not print media paths. Diagnose with `journalctl -u freo-automation` and `journalctl -u freo-playout@<slug>`.

Disabling automation stops new refills; already queued requests may finish. Disabling a track prevents future selection, but an already queued request may play unless the station is restarted by the current media CLI. During a worker or database outage, queued requests continue and Liquidsoap eventually falls back. The worker retries after the database returns; a station socket outage backs off briefly and does not stop other stations. Public installation creates neither categories nor rotations nor demo media. Backups now need PostgreSQL, `/etc/freo`, and `/var/lib/freo/media`; `/run/freo` events are ephemeral, but confirmed history is durable in PostgreSQL.

Phase 6 adds a weekly schedule resolver and ordered clock slots above this selector. The same track/artist separation, relaxation, approved-path queue adapter, and actual-start confirmation remain in use. A clock slot may request a category directly or a named rotation; the latter advances that rotation's cursor. `SelectionDecision` records the clock, slot, assignment, and occurrence so operators can explain confirmed plays. The worker pauses old-clock refills near a transition and resumes with the new clock without restarting Liquidsoap. See [clocks](clocks.md) and [scheduling](scheduling.md).
# Phase 7 media changes

Web uploads are accepted disabled and do not enter the selector. After category assignment and a successful worker verification, enablement changes the PostgreSQL eligibility state without restarting Liquidsoap, Icecast, or the automation worker. Disabling excludes future selections; already queued requests retain their media file and may finish. Decommissioning retains files and history for the same reason.

Browser programming controls are documented in [programming UI](programming-ui.md). The root CLI remains available for recovery.

Phase 9 extends the existing clock selector with exact CART and IMAGING_GROUP requests. A group chooses enabled accepted assets by least recent confirmed start, with a pending hold and bounded separation relaxation. Imaging does not advance the music rotation cursor. Failed imaging slots are recorded and skipped within a bounded clock scan. Liquidsoap receives the same approved request queue URI with an allowlisted path; imaging titles and station names are safely constrained before [Liquidsoap's `annotate:` metadata protocol](https://www.liquidsoap.info/doc-2.2.5/protocols) is used. See [imaging](imaging.md).
