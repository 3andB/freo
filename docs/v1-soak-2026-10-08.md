## Actual defects fixed

1. **Repeated stale microphone failure overrides a later DJ session** (`eb310cf`).
   The worker repeatedly adopted fallback from an already-handled failed engine
   token. It now records a hashed-token acknowledgement and handles that token
   once; a different failed token still recovers. The original regression failed
   before the fix, then focused and actual-engine recovery checks passed.
2. **Icecast 2.5.0 listener inventory/reload deadlock** (`96321ff`). The upstream
   listener XML path acquired real/effective listener configuration read locks
   without releasing them. A two-line source patch releases both after copying
   the IDs. Stock Icecast failed the reproduction; the patched executable passed
   five reloads with real sources/listeners and an installed-staging reload.
   A pinned-source build helper and regression are committed. The installer still
   selects the stock package, so the dependency correction remains a documented
   explicit deployment requirement.
3. **Acceptance fixture corrections** (`d47c644`). These fix the evidenced test
   setup/assertion problems above; they do not redesign or add product behavior.

4. **Anonymous player presence expires after one hour** (`4a3b557`). Successful
   heartbeats did not renew the anonymous signed-session timestamp, and the page
   retained its rejected CSRF token after expiry. Successful presence now renews
   that session; an expired-cookie rejection clears the token for the next beat.
   CSRF checks and admin exclusion remain. Both regressions failed before the
   fix and passed afterward. Actual installed Chromium recovered with responses
   400/200/204 on the same document while audio continued. This affected website
   presence, not the separately collected Icecast stream-listener inventory.

### Quiet intervals and the initially suspected gap

Detection used **-55 dBFS for at least 0.25 s** before the low-rate evidence WAV
conversion. It found **13 quiet fragments, 0.311519–1.290110 s**, associated with
source edges. Two repeated tails split into two fragments under Custom processing.
The full approximate UTC/source mapping is in the JSON evidence; UTC alignment
uses sampled decoder progress and is not sample-accurate engine synchronization.

The initially suspected extra 0.18637 s at 17:46:29 was resolved by measuring the
incoming file: **We Ride On starts with 0.186458 s of quiet** at its recorded
track gain. Added to Forget Me Loop's usual captured 1.10374 s tail, that explains
the observed 1.29011 s interval to within 0.00009 s. The nearby clock warning did
not establish a scheduling fault. No audio/scheduler fix was warranted.

The 17:18:53 transition's 0.311519 s interval combines Still Learning's measured
0.109063 s tail and We Ride On's 0.186458 s intro, with approximately 0.016 s of
additional quiet, compatible with processing/encoding boundary effects; its
precise allocation was not separately measured. Magnetic Petals' quiet ending
accounts for the other short tail-associated fragments; gain, processor state
and MP3 framing shift threshold crossings. The original source scan used a
0.2-second minimum and therefore missed individually shorter head/tail portions;
the final edge audit decoded two-second windows at 48 kHz with recorded gains.
There is **no confirmed unexplained calendar-boundary dropout** in this run.

## Remaining issues, untested areas and release-candidate readiness

Four hours can establish the observed continuous-playback result; it cannot prove
every feature or race bug-free. Real Safari/iPhone, live AI provider calls, varied
geography and external relay ecosystems remain outside this run's evidence.
Release-candidate readiness is **conditional**, not an unconditional sign-off:

- Apply the verified Icecast listener-lock correction on candidate deployments.
  The build helper and patch are committed, but the installer still selects the
  stock package; a fresh default installation was not reset/rebuilt in this task.
- Verify the previously troublesome visualizer on a real iPhone/Safari, including
  failed Enable activation/retry, switching, reconnect and background/foreground.
- Keep the failed co-located-browser workload and clock warnings in capacity
  planning; four hours of browser/visualizer playback did not pass on this VM.
- The initial tag timeout and early DJ-clear timing failure passed unmodified or
  focused follow-up, but their intermittent causes remain unproven.
- Live provider interoperability/quality, physical microphone/mobile installs,
  broad geography and long show recordings remain only partially tested or
  untested as described in the coverage matrix.

The completed stream soak supports further V1 candidate evaluation with these
explicit gates. No main merge, tag, release publication or upgrade
bridge is part of this work.

The optional pinned external central-API source validator, navigation-retention
diagnostic and demonstration screenshot fixtures were not run. Separate opt-in
Phase 2, statistics and system endurance fixtures were not completed as their
own extended workloads; the installed four-hour stream/analytics run must not be
