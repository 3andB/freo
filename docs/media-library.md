# Station media library

Phase 4 stores each track under one station. MP3 is the only format currently accepted end to end: ffprobe confirms an MP3 container/codec, and the installed Liquidsoap decodes it. FLAC, WAV, Ogg/Vorbis, AAC, and M4A remain unsupported until both probe and playout compatibility are tested. No transcoding occurs.

An administrator runs `sudo /opt/freo/venv/bin/flask --app wsgi:app media ingest --station <slug> --file /path/to/audio.mp3 [--title ... --artist ... --album ...]` from `/opt/freo`. The CLI requires root; the public web app has no upload or mutation route. `media list --station <slug>`, `media show <uuid>`, `media verify <uuid>`, `media audit --station <slug>`, `media disable <uuid>`, and `media enable <uuid>` are available. Enable checks file integrity first. Permanent deletion is deferred: disable a track and arrange explicit operator cleanup after backup. Audit reports problems without deleting files.

Ingestion opens a regular source with no symlink following, copies it to root-only staging, enforces a 1 GiB size limit, computes SHA-256, and runs `/usr/bin/ffprobe` with fixed arguments and a 30-second timeout. A corrupt, empty, unsupported, oversized, symlink, or non-regular source is rejected. Staging is removed on failure. The same bytes in the same station return the existing record and do not copy again; the same bytes in another station produce independent storage and a separate row. Source filename is metadata only. The accepted file gets a UUID4-derived internal name and moves atomically into `originals` as root:`freo-playout` mode 0640. The media, station, originals, and playlist directories are root:`freo-playout` mode 0750; staging is root-only mode 0700. `/var/lib/freo` allows traversal but is not broadly writable. The `freo` web user cannot write approved media.

Tags and CLI overrides are trimmed, stripped of controls, and length-limited. Title defaults to the source stem; artist defaults to `Unknown Artist`. Artist and album are text columns, not normalized entities yet. Categories are deferred to the rotations phase. The database records accepted status, enabled state, duration, bitrate, sample rate, channels, size, checksum, and storage key. Only accepted and enabled rows with regular files enter the atomically written station playlist. Storage resolution validates slug and opaque key, rejects symlinks and escapes, and never accepts arbitrary user paths for playout. The public `GET /api/stations/<slug>/media` and `GET /api/stations/<slug>/media/<uuid>` endpoints return safe metadata only, scoped to the station. There is no raw media download route.

Liquidsoap watches the station playlist and uses a generated tone when no playable request is available. An already queued track can survive a playlist update, so CLI enable/disable refreshes the playlist and restarts only that station if its desired state is running. This briefly interrupts that station but leaves `freo-test`, other station processes, Icecast, and web service untouched. No play-history row is written; enqueueing is not proof of actual playback. Future scheduling can replace playlist selection with a controlled request source. The diagnostic fixture remains separate from database-managed stations.

For a complete backup, retain PostgreSQL, `/etc/freo`, and `/var/lib/freo/media`. Playlists can be regenerated from accepted records. Troubleshoot with `flask media verify <uuid>`, `flask media audit --station <slug>`, `journalctl -u freo-playout@<slug>`, local Icecast status, and the public stream. Do not put runtime media or playlists in Git.

## Phase 5 selection

Tracks may be assigned to multiple station-local categories without copying files. The worker only requests accepted, enabled, regular files from the station that owns them. A file missing at selection is skipped; a request that vanishes before a confirmed start is recorded as failed. The root-run media CLI remains the mutation boundary. See [rotations.md](rotations.md) and [automation.md](automation.md).
