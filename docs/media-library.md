# Station media library

MP3 is the only format validated end to end. The trusted `app.services.media.ingest()` service opens a regular source without following symlinks, enforces its 1 GiB internal limit, copies into private station staging, hashes SHA-256, runs `/usr/bin/ffprobe` with fixed arguments and timeout, then atomically installs an opaque UUID-named file. A station-local checksum match returns the existing track without creating a second file. Source names are metadata only. Approved files are never served directly by Flask or Nginx; listeners receive the Icecast stream.

The trusted root CLI remains available: `sudo ./venv/bin/flask --app wsgi:app media ingest --station <slug> --file /path/to/file.mp3`. It retains its existing enabled-by-default behavior and playlist refresh. Root-run `media verify`, `media audit`, and enable/disable commands remain available. The browser uses the **same ingest service** through a separate non-root `freo-ingest` worker. No web request invokes root, sudo, shell, Liquidsoap, or systemd.

Authenticated admins use `/admin/media` or `/admin/stations/<slug>/media`. Single-file uploads are capped at 128 MB in Flask and 129 MB including multipart overhead in Nginx. The web process writes only `/var/lib/freo/uploads`; a private job record refers to a generated UUID basename, never a browser-supplied path. The ingest worker checks the same file with the trusted pipeline and removes staging after processing. Upload status is shown on a job page, with browser upload progress followed by a separate processing state. Invalid audio is rejected by ffprobe; a duplicate links to the existing track. Interrupted jobs marked processing are retried after worker restart. No ZIP, URL, server-path browser, or bulk import is provided.

Web-accepted tracks start **disabled**. An admin can edit title/artist/album, assign existing station categories, then request verify-and-enable. Verification and enable run in the ingest worker; they do not restart Liquidsoap or Icecast. Disabled or uncategorized music is not eligible for category automation. Disabling removes future eligibility; current and already queued audio may finish. Decommissioning disables and uncategorizes but retains the file and history, so queued requests cannot fail from physical deletion. There is no browser physical-delete operation.

Media directories are not world-writable. The web user has upload-staging write access only. The `freo-ingest` worker owns station media directories and approved files. Approved files remain group-readable by `freo-playout`, while the worker does **not** belong to that group and has no Liquidsoap socket access. Existing approved files are re-owned without changing their bytes or group read access during provisioning. The diagnostic stream is separate from this library. Admin mutations require an active global admin session and per-session CSRF token, check station ownership on every request, and write a sanitized `AuditEvent`. The public media API remains metadata-only and read-only.

Backups must include PostgreSQL (including admin and audit records), `/etc/freo`, and `/var/lib/freo/media`. Jobs and `/var/lib/freo/uploads` are transient; do not include them in source control. Check job status, `journalctl -u freo-ingest`, and `flask media verify <uuid>` when troubleshooting.
